[THE DUAL-LAYER PRODUCT ARCHITECTURE]
1. Inbound Layer (Protocol-facing):
   - Sybil detection and bot-cartel filtering for token launches/airdrops.
   - Uses on-chain graph analysis & community detection heuristics (Louvain / connected components clustering) on wallet funding graphs and transaction timing, providing explainable, tiered allocation scores.
2. Outbound Layer (User/Wallet-facing):
   - Browser extension that acts as a pre-signing transaction shield.
   - Sits between dApps and wallets (like MetaMask), simulates transactions before signing, and warns users of asset drainers, honeypots, and malicious Permit2 approvals.

[CRITICAL ARCHITECTURAL DECISION — DO NOT OVERRIDE]
- Initially, we considered running an "AI agent in a sandbox to read smart contract code" to detect scams.
- THIS APPROACH WAS REJECTED BY OUR SENIOR SECURITY ARCHITECT FOR CRITICAL REASONS:
  1. Latency: An LLM reading bytecode/Solidity takes 3-10 seconds. Web3 transactions require <100ms response time.
  2. The Real Threat Model: Most phishing attacks (Permit2 drainers, spoofed claim sites) do NOT run malicious code. They call 100% legitimate, verified contracts (Uniswap Permit2, OpenSea Seaport, standard ERC-20) with POISONED PARAMETERS (e.g., unlimited approvals or zero-cost transfers to a hacker address). An LLM inspecting contract code will mark it as "clean" while the wallet gets completely wiped out.
  3. The Proven Industry Standard: Like Blockaid ($83M funded), Pocket Universe, and Tenderly, Aegis3 uses DETERMINISTIC EVM STATE SIMULATION (dry-running transactions on forked state via EVM RPC / Anvil) to measure actual STATE DIFFS (balance changes, token transfers, approval deltas).
  4. Where AI Actually Fits: AI/LLMs are used ONLY to translate the simulated state diff into plain-English human explanations, NOT to detect the exploit itself.
